# Git 和 GitHub 支持

## 适用范围

Luma 0.7.8 支持本地版本管理与远程同步。Git 是版本管理工具；GitHub 是可托管 Git 仓库的网站，两者不是同一件事。本地提交无需 GitHub 账号。模型推理与 Git 同步分别连接各自的服务，Git 的网络请求由用户电脑发起。

本指南面向 Latest 0.7.8。0.7.2 LTS 不包含新增 Git 管理页面。

## 一、准备环境

1. 从侧栏选择一个本地项目，打开左侧的 Git 分支图标。
2. 尚未检测到 Git 时，点击下载 Git，在官方安装程序中安装，然后重新检测。
3. 已安装却未识别时，打开 Git 环境，填写 git.exe 的完整路径。留空保存恢复自动检测。
4. 独立聊天不启用 Git；请先添加项目。

Luma 不捆绑 Git，建议使用支持 switch 与 init -b 的 Git 2.28 及以上版本。手动路径也用于 Agent 的 git_diff；终端里的 git 命令仍由系统 PATH 决定。

[Git 官方下载](https://git-scm.com/downloads)

## 二、初始化与提交身份

没有仓库时点击初始化仓库，选择初始分支名称。可选择添加基础 .gitignore，已有文件不会覆盖。初始化不自动提交，也不上传。

如果项目是上级仓库中的子目录，页面会显示实际根目录，操作范围是整个仓库。请先核对路径。

提交身份填写姓名和邮箱，会出现在提交历史中。默认仅用于当前仓库；勾选全局选项才修改这台电脑上的默认 Git 身份。身份不是 GitHub 登录凭据。缺少身份时仍可查看和暂存文件。

## 三、日常本地工作流

| 区域或操作 | 含义 |
| --- | --- |
| 未跟踪 | 尚未纳入 Git 的文件 |
| 未暂存 | 工作区相对暂存区的修改 |
| 已暂存 | 下一次提交将保存的内容 |
| 取消暂存 | 撤出本次提交，保留文件内容 |
| 提交 | 将已暂存内容保存为本地版本 |
| 文件审阅中的保留 | 接受 Agent 追踪修改，不等于 Git 提交 |

1. 点击文件查看逐行差异或修改前后对照。
2. 暂存需要保存的文件，可以单文件或按组批量操作。
3. 填写提交说明，检查确认窗口后提交。
4. 在提交历史中查看最近 40 次提交，点击提交再查看文件差异。

生成提交说明会把暂存差异发送给当前模型，最多使用约 24 KB，发生截断时会提示。结果是可编辑草案，不会自动提交。提交失败会保留说明，Git 钩子和签名设置仍生效。

本地分支支持创建和切换。有未提交修改时会阻止切换，请先提交或在外部工具处理。

## 四、连接 GitHub 或其他远程仓库

Luma 管理已有仓库地址，不自动创建 GitHub 仓库。先在 GitHub 创建仓库，复制 HTTPS 或 SSH 地址，再在 Git 页面打开远程设置，添加远程。

- 远程名称一般填写 origin。
- HTTPS 示例：https://github.com/your-account/your-project.git
- SSH 示例：git@github.com:your-account/your-project.git
- 也支持本地仓库的绝对路径，方便内网或本机测试。

不接受包含密码/令牌、查询参数的地址，也不支持自定义传输协议。可编辑普通远程地址，或移除本地远程配置。移除会同时移除本地跟踪引用，但不会删除远程服务器仓库、本地分支或项目文件。

如果已有独立推送地址或多个地址，界面会展示并要求在外部工具调整复杂配置，避免意外推送到错误目标。GitHub 地址提供“在 GitHub 打开”入口。

## 五、认证与连接测试

Luma 复用系统 Git 的凭据管理或 SSH 密钥，不保存 GitHub 密码或个人访问令牌。应用内网络操作不等待终端密码输入；没有可用凭据时，会返回明确错误。

### HTTPS

可使用 Git for Windows 配套的 Git Credential Manager。首次登录或凭据过期时，在系统 Git 终端对该仓库执行一次 fetch，按照 Git 凭据管理器提示完成登录，再回到 Luma 测试连接。应使用 Git 环境中指定的同一个 Git 安装。

```text
git -C "你的项目目录" fetch origin
```

GitHub Desktop 登录不保证另一套系统 Git 已获得凭据。不要把令牌粘贴到远程 URL 或提交说明中。

[GitHub 凭据缓存说明](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git)

### SSH

先在系统环境配置 SSH 密钥、代理及已验证的主机记录。Luma 使用批处理 SSH，不弹出密码输入，也不会自动接受陌生主机密钥。提示主机验证失败时，请先在系统终端核验服务器身份后连接，不能关闭主机验证来绕过问题。

[GitHub SSH 指南](https://docs.github.com/en/authentication/connecting-to-github-with-ssh)

测试连接只验证读取权限。是否拥有推送权限，要以实际 Push 结果为准。仓库不存在与无访问权限有时会得到相似错误，需要检查账号、地址及组织权限。

## 六、Fetch、Pull 与 Push

| 按钮 | 行为 | 是否改变工作文件 |
| --- | --- | --- |
| Fetch | 获取远程分支信息，更新本地远程跟踪引用 | 否 |
| Pull | 从选定远程分支进行快进更新 | 可能 |
| Push | 上传当前分支已提交历史，并设置跟踪分支 | 否 |

每次操作都会显示远程目标；Pull 和 Push 还要确认分支。Push 不上传未提交修改，也不执行强制覆盖。

建议顺序：检查并提交本地修改，Fetch 查看远程状态，需要时 Pull，再 Push。首次推送可填写与本地同名的远程分支。

领先/落后数字基于本机保存的远程信息，不是实时联网查询。Fetch 后再判断是否需要同步；没有跟踪分支时会明确提示。

Pull 要求工作区干净，并只接受快进。如果本地和远程都出现不同提交，Luma 会停止，交由外部工具合并或变基，不自动创建合并提交或藏起本地修改。

[Git Pull 快进更新说明](https://git-scm.com/docs/git-pull)

## 七、冲突与失败排查

- 未提交修改：先提交，或在外部工具暂存/整理工作区，再 Pull 或切换分支。
- 历史分叉/推送被拒绝：先 Fetch，查看领先/落后；在外部工具合并或变基后回来刷新，切勿盲目强推。
- 合并冲突或未完成的变基：页面会标识冲突并阻止同步，使用外部编辑器/Git 工具处理，完成后刷新。
- 仓库配置变化：刷新后重新确认目标，避免操作陈旧状态。
- 网络、认证或权限错误：检查远程地址、账号权限、凭据及代理；错误区会显示原因。
- 超时：远程操作最多等待约 120 秒。本地不能据此断定服务器没有执行，请先 Fetch/刷新核对状态，再决定是否重试。

本版没有冲突编辑器、强制推送、自动合并、自动变基、远程分支删除、仓库克隆或 PR 管理。必要时可配合 GitHub Desktop、VS Code 或系统 Git 使用。
